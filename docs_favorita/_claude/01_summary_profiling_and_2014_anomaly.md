# 01. Саммари треда: bronze, профилирование, аномалия 2014 года

Период: 2026-10-23 … 2026-10-24. Проект: прогнозирование продаж Favorita (Kaggle).

## 1. Принятые решения по архитектуре данных

| Тема | Решение | Обоснование |
|---|---|---|
| Слои | landing → bronze → silver → gold (medallion) | у каждого слоя свой контракт; landing хранит исходные CSV неизменными |
| Контракт bronze | типы заданы явно, значения не изменены, число строк равно CSV | очистка (заполнение NULL, обрезка возвратов, дубли) относится к silver |
| Инструмент | DuckDB поверх parquet, pandas только для небольших результатов | 125 млн строк train не помещаются в pandas; один инструмент на весь путь |
| Типы | задаются при чтении CSV (`read_csv(columns=...)`), не после | ошибки автоопределения не попадают в bronze |
| Где работать | DuckDB UI — черновик; всё, что влияет на результат, — в ноутбуке в репозитории | состояние UI не попадает в Git |
| Gold | несколько EDA-витрин разного зерна (дата; дата × магазин; дата × магазин × family; детальная на подмножестве) | зерно определяется вопросом анализа |
| Единица журнала решений | проблема из реестра, а не столбец | проблемы затрагивают несколько полей и таблиц |

## 4. Главная находка: неполная запись данных в 2013 – начале 2015 года

**Суть.** Фиксированный блок примерно из 665 товаров целыми семействами (PRODUCE 243/244, HOME CARE 69/69, HOME AND KITCHEN I/II, CELEBRATION, LADIESWEAR, PLAYERS AND ELECTRONICS, SCHOOL AND OFFICE SUPPLIES, PET SUPPLIES, MAGAZINES, около половины BEVERAGES) в отдельные месяцы отсутствует в train целиком. Это ходовые товары: 90 % блока в марте 2014 продавались каждый день.

**Присутствие блока в train:** 2013 — нет весь год; 2014-01 — 97 %; 2014-02 — 1 %; 2014-03 — 100 %; 2014-04…06 — 0–1 %; 2014-07 — 98 %; 2014-08 — 2 %; 2014-09…12 — около 99 %; 2015-01…04 — 14–16 %; 2015-05 — 49 %; с 2015-06 — 98–99 %.

**Доказательства:**
- Ступеньки числа товаров приходятся ровно на 1-е число месяца; на границе 2014-03-31 → 04-01 товаров 2574 → 1927.
- Во всех 47 магазинах из 47 изменение в одну сторону (медиана −21 %).
- Число чеков не падает (+1,7 %), а unit_sales падает на 32 %.
- Сезонность отвергнута (в 2013, 2015, 2016 нет такого рисунка).
- Прореживание по объёму отвергнуто (доля пропавших по децилям продаж U-образная).
- Конец NULL в onpromotion (2014-03-31) совпадает с одной из границ.

**Почему это проблема:**
1. Правило «нет строки = 0» для этих товаров и месяцев даёт ложные нули.
2. Суммарные продажи до 2015-06 занижены, рост динамики 2013–2015 частично фиктивен.
3. Сравнения периодов в EDA сопоставляют неполные данные с полными.

**Предложение для журнала решений (не принято, решает автор):**
- Вариант A (рекомендован): восстанавливать нули только с 2015-06-01; около 26 месяцев истории, два годовых цикла.
- Вариант B: с 2014-04-01 для товаров вне блока; для товаров блока в проблемных месяцах продажи считать пропуском (NaN); 2013 год для блока не использовать. Больше истории, но сложнее витрины.
- Для EDA «общая динамика» строить с 2015-06 либо без товаров блока.
